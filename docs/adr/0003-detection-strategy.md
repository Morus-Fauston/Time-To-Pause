# ADR-0003: 包名白名单 + Activity 名称检测，不用内容分析

## Status

Accepted

## Context

需要检测用户是否在看短视频。可选的检测策略范围很广：从最简单的包名匹配到复杂的屏幕内容分析（OCR/深度学习/截图）。检测精度和用户隐私之间存在根本性矛盾。

## Decision

采用**包名白名单 + Activity 名称**的轻量检测方案，明确不采用任何内容分析技术。

- 纯短视频 App（抖音、快手等）：只用包名匹配
- 复合 App（B 站）：包名 + Activity 名称双重校验
- 不检测微信视频号、浏览器网页版等非主流入口

## Considered Options

- **截图 + 图像识别** — 能达到最高精度（甚至识别出用户在刷什么视频），但需要 `MEDIA_PROJECTION` 权限（需用户手动确认录屏），且每次截图都有隐私风险。性能开销大，违反"CPU < 3%"的要求。
- **AccessibilityService 监听页面内容** — 可获取 Activity 名和页面文本，但权限门槛高，OPPO/vivo 等品牌对无障碍服务的限制越来越严。
- **全 Activity 白名单（所有入口都检测）** — 覆盖微信视频号、浏览器等渠道，但技术成本大幅上升且维护成本高（需要跟踪每个 App 的 Activity 名变化）。

## Consequences

- 检测精度有限，微信视频号、浏览器短视频等渠道不在范围内
- "宁可漏检不误伤"的原则保护了用户对长视频等正常使用的体验
- 白名单需要持续维护（尤其 B 站 Activity 名随版本变化）
- 不上传任何用户数据，所有检测在本地完成

## Why This Is Surprising

用户可能期望一个"防沉迷 App"具备某种 AI 检测能力。但刻意选择简单的包名匹配而非更"智能"的技术，是因为隐私保护在这个场景下比检测精度更重要。这也是产品定位"非监控"的体现。
